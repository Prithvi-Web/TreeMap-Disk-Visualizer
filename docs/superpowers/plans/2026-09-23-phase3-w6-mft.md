**Goal:** on an NTFS volume, with the user's explicit consent to an elevation prompt, enumerate the scan root's subtree from the master file table in a few large sequential reads instead of one listing call per directory — producing the same columns the native listing produces, so everything downstream (the store, the JSON, the equivalence gate) is unchanged — and prove it on a real volume before the app ever offers it.

**Architecture:** a new crate `tm-mft` holds everything portable: the record parser, the run-list decoder and the tree builder, each tested on synthetic byte buffers on every platform, exactly as the Windows listing's parsers are. A `cfg(windows)` module reads the volume. The app process never runs elevated: a tiny binary, `tm-mft-helper.exe`, is launched through Electron's elevation prompt for one scan, reads the volume read-only, writes the root's subtree as columns to a file under the app's temp folder, and exits; the app reads the file and hands the columns to the same ingest the native engine uses. Before the result is trusted, the app cross-checks 1,000 random entries against `GetFileInformationByHandleEx` and discards the whole result on the first mismatch, falling back to the listing walk with the reason.

**Tech stack:** Rust (`windows-sys` 0.61.2, already in the lock file; no new crate), napi for the cross-check, Electron main-process elevation (`ShellExecuteExW` with the `runas` verb), TypeScript strict, node:test via tsx.

**House rules:** unchanged (test first with a recorded mutant per behaviour, the strict lint set, `// SAFETY:` on every `unsafe`, cross-target clippy, never the owner's folders, never a number that was not measured, nothing downloaded). CI is Node 20; the toolchain is the pinned 1.98.1.

## Decisions fixed by this plan

| # | Decision | Why |
| --- | --- | --- |
| W6-1 | **The app never runs elevated.** Only `tm-mft-helper.exe` does, for one scan at a time, launched with the `runas` verb from Electron's main process after a one-sentence explanation. Declining the prompt is not an error: the scan runs on the listing walk and `engineReason` says elevation was declined. | D7; the master prompt §7.2 ("if elevation is declined, this is not an error"). |
| W6-2 | **Read-only, by construction.** The volume is opened `GENERIC_READ` with `FILE_SHARE_READ \| FILE_SHARE_WRITE`; the helper contains no call that writes, deletes or renames anything except its own output file, which must be under the app's temp folder (validated before any read). | The master prompt §3.1 and §7.2. |
| W6-3 | **NTFS only, refused cleanly otherwise.** `GetVolumeInformationW`'s file-system name must be `NTFS` and `FSCTL_GET_NTFS_VOLUME_DATA` must succeed; ReFS, FAT32, exFAT and network paths are refused with the reason, before anything is read. | §7.2. |
| W6-4 | **Every record is read in bulk.** The helper reads `$MFT`'s own record (0), decodes its `$DATA` run list, and reads each extent sequentially in cluster-aligned 1 MiB chunks. `FSCTL_GET_NTFS_FILE_RECORD` (one call per record) is not used: it is the per-entry cost this mode exists to avoid. | The WizTree technique; §7.2. |
| W6-5 | **Extension records are merged by their base reference; `$ATTRIBUTE_LIST` is never read.** Every in-use record is parsed; a record with a non-zero base reference contributes its attributes to its base. This handles attribute lists — resident or not — without reading them. | Simpler and complete: every attribute lives in some record the sequential read visits. |
| W6-6 | **The legacy walker's semantics, rule for rule** (the equivalence gate compares against it): names are the `$FILE_NAME` attributes in the POSIX (0), Win32 (1) and Win32&DOS (3) namespaces — a DOS-only name (2) is never an entry; each such name under a directory is one entry, so a file with two links in two directories is two entries, and the hard-link rule is the listing's (the file reference is the id). Size is the unnamed `$DATA` stream's real size (resident: the value length; non-resident: the real-size field); alternate data streams are not counted, as `lstat` does not. Times are `$STANDARD_INFORMATION`'s last-write and last-access, through the listing's `filetime_ms`. Reparse points use the listing's `reparse_target_len` on the `$REPARSE_POINT` value (its layout is `REPARSE_DATA_BUFFER`'s); the dataless flag is the listing's `is_dataless`. A directory's children are ordered as NTFS indexes them — upper-cased UTF-16 through the volume's own `$UpCase` table (record 10), compared unit by unit — which is the order `readdir` and the native listing return on Windows (`SORT_CHILDREN` is false there). | Byte-identical output by construction; DESIGN §5.2 item 5 already makes directory times come from the directory itself, which is what `$STANDARD_INFORMATION` holds. |
| W6-7 | **One intentional difference, listed in DESIGN §16 when this lands:** the elevated reader sees directories the unelevated walker is refused (`denied`). They are reported like any other directory. The equivalence proof on CI runs both engines as administrator, where the two agree. | An administrator's metadata view is the point of the mode; hiding it would be a lie of omission, and it is named rather than smoothed. |
| W6-8 | **The cross-check is the gate at run time.** 1,000 entries drawn uniformly at random from the result (all of them when there are fewer), each opened by the app — unelevated — with `FILE_READ_ATTRIBUTES`: size, last-write time and kind must equal the MFT's. An entry the app cannot open (denied, vanished) is skipped and replaced by another draw; the check fails on the first mismatch and the mode is switched off for that volume for the session, with the entry and both values in `fallbackReason`. | §7.2 ("If they diverge, disable turbo mode and report why"). |
| W6-9 | **Proven on CI or shipped labelled.** CI's Windows runner runs as administrator without a UAC prompt, so M5 runs the real reader on the runner's volume. The elevation prompt itself (M6's Electron part) cannot run on CI; if nothing proves it end to end, the setting ships with `engineReason: 'not verified on this build'`, and the stats say so on every scan that uses it. | P3-10. |

### Corrections found while building M1–M3 (23 September 2026) — binding for M4–M6

1. **The fix-up stride is always 512 bytes** (`UPDATE_SEQUENCE_STRIDE`), whatever the disk's sector size: NTFS protects every 512 bytes of a record. M4 must pass the constant, never `NTFS_VOLUME_DATA_BUFFER.BytesPerSector` (4,096 on a 4K-native disk, which would refuse every record).
2. **`$MFT` needs a bootstrap W6-5 does not cover.** A fragmented `$MFT`'s later `$DATA` extents live in its own extension records, found only by reading the first extent: read record 0, then the records whose base is 0 with `$MFT`'s sequence, collect their `data_extents`, concatenate in VCN order, and only then build the extent map.
3. **Stop at `$MFT`'s initialized size**, not its allocated size: records past it are stale disk contents and can look like in-use FILE records.
4. **Rules W6-6 did not list, built and tested:** records 0–15 (the metafiles) are never entries; the directory bit comes from the record header (`$STANDARD_INFORMATION` never stores `FILE_ATTRIBUTE_DIRECTORY`); a directory whose name holds a separator is refused as the walk refuses it; a reparse-point root is refused (`RootIsReparsePoint` — the listing follows a mount point's or a sync client's filter, the MFT cannot); a directory reached twice (corruption, a cycle) is refused instead of looped.
5. **`fastPath` needs a value for this mode.** `tm_walk::FastPath` has no MFT variant; `build_tree` reports `Unavailable` as a placeholder, pinned by a test so that adding `FastPath::Mft` ("mft" in the stats — an additive change, D6) forces the update. Add it in M6, when the mode is wired.
6. **M5's hard-link fixture:** the listing reports each name's size and times from its parent's index copy, which NTFS refreshes only for the name the file was opened through — create the links AFTER the file's last write, or the two walks disagree with the MFT being the one that is right.
7. **Divergences to prove or name in M5:** a reparse point whose value is non-resident is omitted and counted unreadable (the listing would read it from disk); the allocation column's rules (resident = length rounded up to 8; sparse/compressed = clusters actually allocated) against the listing's `AllocationSize`; NTFS 3.0 records without a record number are refused.
8. **Stats:** `build_tree` times only itself; M4 adds the read time. `workers_peak` 1, `climb_steps` 0.

### Corrections found while building M4–M5 (23 September 2026) — binding for M6

9. **A raw read sees `$MFT` as NTFS last flushed it, not as it is now.** Recent creates, writes and renames can be missing or stale for seconds. M5 retries for up to 120 s. **M6's cross-check (W6-8) must not fail on a file changed since the last flush**: sample only entries whose own last-write time is older than the read's start by a margin, and on a mismatch re-read the entry live once before calling it a divergence. Otherwise the first-mismatch rule disables the mode for no fault of the reader.
10. W6-4's "1 MiB chunks" cannot hold with clusters larger than 1 MiB (2 MiB clusters exist since Windows 10 1709): reads are up to one cluster where a cluster is larger.
11. The initialized size is the smallest of record 0's initialized size, its data size and `MftValidDataLength`, in whole records.
12. A torn in-use record refuses the whole read after one re-read (skipping it would drop its entries silently, which the cross-check cannot see); unwritten (`BAAD`/no signature) and not-in-use records are skipped.
13. `read_volume(root, …)` derives the volume from the root, so the helper's arguments are `<root> <output file>` (the volume argument is dropped). A root reached through a junction onto another volume is refused (the serials differ).
14. The record number field is 32 bits in the header (M1); a volume with 2³² or more records is refused, not misread.
15. M5 cannot catch a defect in `stage_record` — both engines stage through it (by design, M3).

## Fixed interfaces

### `tm-mft` (Rust, portable)

```rust
/// One parsed FILE record, with its extension records' attributes merged in.
pub struct Record {
    pub number: u64,              // the record's own number (48 bits)
    pub sequence: u16,
    pub in_use: bool,
    pub is_dir: bool,
    pub base: u64,                // 0 for a base record
    pub std_info: Option<StdInfo>,
    pub names: Vec<FileName>,     // every $FILE_NAME, DOS-only ones included (the builder drops them)
    pub data_size: Option<u64>,   // the unnamed $DATA stream's real size
    pub reparse: Option<Vec<u8>>, // the $REPARSE_POINT value (REPARSE_DATA_BUFFER layout)
}
pub struct StdInfo { pub last_write: i64, pub last_access: i64, pub attributes: u32 }
pub struct FileName { pub parent: u64, pub parent_seq: u16, pub namespace: u8, pub name: Vec<u16> }

pub enum RecordError { BadSignature, FixupMismatch { sector: usize }, Truncated, BadAttribute { offset: usize } }

/// Applies the update-sequence fix-ups in place and parses one record.
pub fn parse_record(buf: &mut [u8], bytes_per_sector: usize) -> Result<Record, RecordError>;

/// Decodes a non-resident attribute's run list into (starting LCN, cluster count) extents; a sparse run is None.
pub fn decode_runs(runs: &[u8]) -> Result<Vec<(Option<u64>, u64)>, RecordError>;

/// The scan root's subtree, in the listing's column shape (tm_walk::WalkOutput).
pub fn build_tree(records: &RecordTable, root: u64, upcase: &[u16], want_atime: bool) -> Result<tm_walk::WalkOutput, BuildError>;
```

### `cfg(windows)` reader and helper

```rust
pub fn read_volume(volume: &str /* "C:" */, root: &Path, want_atime: bool) -> Result<tm_walk::WalkOutput, MftError>;
```

`tm-mft-helper.exe <volume> <root> <output file>`: exit 0 and a columns file on success; exit 2 with one line on stderr naming the refusal otherwise. The columns file is a versioned little-endian dump of `WalkOutput`'s columns (a 16-byte header: magic `TMMFT001`, entry count, flags), read by `tm-node`'s `mftTake(path)`.

### Node

`engine` setting gains `'ntfs-mft'` (Windows only; the Settings row is hidden elsewhere). `nativeEngine.ts` gains `runMftWalk(scan, store, rootPath)`: elevate → wait for the helper → `mftTake` → the cross-check (`mftCrossCheck(paths, expected)` in `tm-node`) → ingest, or fall back with the reason.
