## 0. The size question
Priority order: installed size, then idle memory, then responsiveness.
1. Tauri removes Chromium but not the JS runtime. Electron Framework.framework = 228,592 KB (`du -sk`). /usr/local/bin/node v24.16.0 is universal (243,486,096 B); its arm64 slice = 120,573,328 B (`lipo -detailed_info`). Tauri + Node sidecar swaps ~229 MB of Electron for ~121 MB of Node plus the shell (to measure).
2. Dead weight removable with either shell (Phase S): MCP SDK + zod (only src/mcp/* imports them; nothing in the server or desktop entry imports src/mcp), exceljs dist/, pdfmake build/, better-sqlite3 C sources, the Windows gdu the app never runs.
3. The smallest TreeMap has no Node runtime: a Rust backend (Phase R); the ~121 MB runtime leaves only when the last route leaves.
4. Recommended order: Phase S (measure, prune) → Phase T (Tauri 2 shell + Node backend as sidecar) → Phases 5–8 (amended) → Phase R (backend into Rust crates behind the existing tm-node bridge, service by service; TS stays as the reference; HTTP layer last; then Node leaves the bundle). OQ1 = whether the next release waits for Phase R.

To measure: Tauri shell binary (release), pinned official Node per platform, pruned node_modules total, all Windows figures.
- Stage R (Rust backend): public 1.6 MB. To measure: Rust backend + shell binary; anything Phase 7 ships (ONNX Runtime). (Today's Rust core 1,390,688 B is a reference point, not a prediction.)

### 0.2 Options
(a) Tauri + Node sidecar, then backend to Rust — RECOMMENDED: backend out of the window's process early (likely lag cause); two risky changes kept apart; sidecar lifecycle/stdio/packaging reused. (b) Rust backend first inside Electron — rejected (no size gain until the end; Phase 7/8 built twice). (c1) Rust HTTP front proxying to Node — rejected (two copies of security middleware; SSE through a proxy). (c2) trimmed custom Node — only as experiment M6. (c3) Bun/Deno — rejected (different runtime under a safety-critical suite). (c4) keep Electron and prune — leaves 228,592 KB. (c5) Node SEA — same binary + blob; cannot load .node addons without writing them to disk.

## 2. Design decisions
Q1 Backend under Tauri: official Node binary as a Tauri sidecar, version pinned (OQ2), SHA-256 checked at staging like fetchGdu.js; backend as ordinary files in resources: package.json, dist/, public/, node_modules/ (T-4 manifest only), native/prebuilt/<platform>-<arch>/, gdu per OQ4. Three native addons as real files: treemap_core.node (N-API), better-sqlite3 (built for the pinned Node via npm ci under it), sharp + @img/sharp-libvips-*. Signing macOS unsigned as today: ad hoc every Mach-O innermost first (backend node, every .node, libvips dylib, gdu), then sidecar, then app; no hardened runtime (port afterPack.js); CI codesign --verify --deep --strict. Future Developer ID: hardened runtime + Node JIT entitlements + disable-library-validation (to verify); notarize. Windows unsigned; node.exe keeps its signature (to verify). Lifecycle: shell spawns `node <res>/backend/dist/desktop/sidecar.js` with its own env (TREEMAP_SHELL=tauri, TREEMAP_APP_EXECUTABLE, TREEMAP_RESOURCES_DIR, no NODE_OPTIONS); token = first stdin line. Sidecar binds 127.0.0.1:0, writes one ready line {v, event:'ready', port, pid, version, nativeVersion, protocol, appDataDir, portable, prefs}; stdout = protocol lines only (console.log → stderr as src/mcp/index.ts does); shell waits up to a limit from M5. Crash: unasked exit → one dialog "TreeMap's engine stopped" (Restart, Quit, Copy details); restart → new sidecar + window to new origin; start-up checks run; never a silent loop. Shutdown: {cmd:'shutdown'} → RunningServer.shutdown (server.ts:241-269) → exit; kill after 5 s (src/index.ts limit). No orphans: stdin EOF → shutdown (precedent src/mcp/index.ts:34); Windows Job Object KILL_ON_JOB_CLOSE; Linux PR_SET_PDEATHSIG; a backend lock file in the data folder (OQ11).
Q2 UI↔backend: keep HTTP on 127.0.0.1 with per-launch token + SameSite=Strict HttpOnly cookie; window loads http://127.0.0.1:<port>/ as today; Tauri IPC only for native shell capabilities. Rejected: IPC for the API; tauri:// page calling 127.0.0.1 (cross-site); custom-scheme proxy (no SSE streaming, to verify). CSP byte-identical plus Tauri's IPC source only when TREEMAP_SHELL=tauri (origins to verify: ipc://localhost / http://ipc.localhost; T-12). One capability for window "main", remote URL http://127.0.0.1:* (port wildcard to verify; else added at run time for the bound port); page granted only TreeMap's commands + core:event listen/unlisten; no fs/shell/dialog/opener/updater/notification permission to the page; all commands async. Bridge = initialization script injected only on the expected origin, keeping window.treemapDesktop names: getPathForFile → ''; resolveScanPath → resolve_scan_path; requestScans → request_scans (ScanQueue in Rust); onScanPath → event treemap:scan-path; onCommand → event treemap:command; scanProgress/scanFinished → commands; NEW onDragHint (event treemap:drag-hint), openExternal (http/https/mailto only; window.open wrapped), openPrivacySettings('full-disk-access') (one fixed URL; fixes D-2); later requestDeepTierConsent (Rust dialog → sidecar stdin).
Q3 Now (Phase T): the whole shell in Rust (supervisor, window, guards, bridge, ScanQueue, folder intake, single instance, menu, tray, notifications, attention, progress, power hooks, updater, crash net, downloads). Stays TS in the sidecar: every sentence, number, prefs I/O with its portable rule (moved electron/lib → src/desktop/*). Later (Phase R): backend becomes a Rust HTTP server — (1) reference first: goldens today = 11 read endpoints, macOS only (tests/fixtures/golden/responses.json) → extend to all 141 openapi routes + live Node-vs-Rust comparison on every leg; (2) logic service by service into Rust crates behind tm-node; TS stays as reference until the group's comparison is green; (3) HTTP layer last (axum, treemap-server crate) carrying hostGuard, token/cookie, CORS, rate-limit lanes, CSP, sameOriginGuard, SSE, streamed bodies, proven by the API test files; (4) Node leaves the bundle; web/Docker/VS Code switch to the treemap-server binary. Groups: W1 pure computations; W2 data stores (index → rusqlite, reads existing DBs unchanged); W3 scan orchestration; W4 reports; W5 platform/* (8,919 lines); W6 fleet, cloud OAuth, compression; W7 safety-critical writers (cleaner/trash, Time Capsule, offload + verify, autopilot, path guards, audit) — strictest gates; W8 HTTP; W9 cut-over. Backend outside src/ui = 56,328 TS lines (services 34,074; platform 8,919; api 7,750 across 141 routes). Not worth it: rewriting the UI; early Rust ports purely for size while Node remains; a Rust MCP server for desktop.
Q4 WebView differences: SSE (WebKit reconnect, 6-connections limit, hidden-window throttling vs the page's scan watchdog); canvas perf (WebKitGTK CPU); fonts; backdrop-filter needs -webkit- twin (only 3 style files have it vs 21 lines) → build-ui lint; drag-and-drop (native file drop disables HTML5 file drops; on Windows also in-page HTML5 dragging — the cart drags rows, to verify); window.open for x-apple.systempreferences and OAuth (WKWebView ignores without delegate) → bridge; clipboard (secure context for loopback to verify; execCommand fallback 115-tooltip.js:369-373); downloads (<a download>, blob:) need a Rust download handler; blob: worker CSP worker-src blob:; ⌘R/⌘K/⌘B/⌘, double-firing once onCommand is wired; localStorage (D-3, OQ12). UI tested per WebView by a --treemap-selftest mode (test-only cargo feature) driving the page with webview.eval, on 3 OSes (Linux xvfb); no WebDriver (tauri-driver has no macOS); no new npm dependency.
Q5 Updater: tauri-plugin-updater with an owner-held key (OQ3); Windows download → Restart Now/Later; macOS check-and-offer while unsigned (ad-hoc signature changes each build; Full Disk Access may drop after auto-install, to verify); every 6 h, first at 15 s. Installers: macOS arm64 dmg, zip, .app.tar.gz + .sig; Windows x64 NSIS per-user with directory choice; Linux AppImage built+tested, not released (OQ5). Portable: zip + marker on every OS; webview data inside TreeMap-Data or non-persistent; a test proves nothing written outside (D-4). Scan with TreeMap registers TREEMAP_APP_EXECUTABLE (T-6), re-registered after migration (T-25). Single instance → same queue.
Q6 Tests/CI: every leg on the exact shipped Node (.node-version via setup-node). nativeStoreFill installed-binary case retired; bench --runtime=electron → --runtime=sidecar; desktopPolish pure cases stay TS (src/desktop) or port to Rust from shared vectors; main.js-wiring cases → Rust tests + self-test scenarios. Equivalence: served index.html byte-identical; API tests against the staged sidecar (TREEMAP_TEST_BACKEND=sidecar); self-test scenarios mirror desktopPolish; the whole safety suite against the staged sidecar on four legs. macOS/Windows/Linux legs gain fmt, clippy, cargo test, debug build, self-test.

## 8. T-13 spike results (30 Sep 2026) — facts that CHANGE this plan
Source: `docs/desktop/TAURI-FACTS.md` (every fact cites a crate source line or a run log). Versions pinned with `=`: tauri 2.12.0, tauri-build 2.7.0, tauri-plugin-single-instance 2.5.1, tauri-plugin-updater 2.13.1 (tauri-cli 2.12.0); all need Rust ≥ 1.90; the repo's 1.98.1 builds them. Tauri 3 is alpha.
- **Size (measured, macOS arm64):** minimal shell 3,068,464 B with `opt-level="s"`, LTO, 1 codegen unit, strip, panic=abort; 4,175,952 B with panic=unwind; the spike with five plugins 4,707,392 B ("s"). `.app` ≈ binary + 24 KB. **Recommended profile: "s" with panic="unwind"** (a panic in an async task survives; with abort any panic kills the app). Stage T ≈ Node's arm64 slice (120,573,328 B) + ~3-5 MB shell + the pruned backend.
- **Plugins inject JavaScript into every page, including TreeMap's remote page:** the dialog plugin replaces `window.confirm` with an async function (so `if (confirm(...))` sees a truthy Promise — a delete confirmation that always passes); the opener plugin hijacks `target=_blank` clicks; the notification plugin replaces `window.Notification` and trips TreeMap's CSP. **Decision: register ONLY single-instance and updater.** Dialogs via the `rfd` crate from Rust; links via `tauri_plugin_opener::open_url` as a free function or the `open` crate; notifications via a notification crate directly. A test asserts `window.confirm`, `window.Notification` and link clicks are untouched in the page (T-26).
- **`window.prompt()` returns null immediately in WKWebView:** TreeMap's three prompt flows (`src/ui/app/105-query-grammar…js:508`, `230-allocation-diagnostic.js:226` and `:250`) would silently cancel → in-page dialogs (new task, before T-26).
- **`on_permission_request` is mandatory** (without it wry grants camera/microphone to any page); deny all but notifications/clipboard write, matching `electron/lib/guards.js`.
- **`on_download` is mandatory** (without it WebKit saves into ~/Downloads — it happened in spike run e4); `<a download>` works for same-origin and `blob:` URLs; a synchronous rfd save panel works inside the handler.
- **Native file drop hides every drag from WebKit on macOS too** → the cleanup cart's in-page row dragging very likely breaks (from source; a 2-minute hand check is listed in the facts doc). T-18 must keep in-page drags working (native drop off + bridge, or pointer-based cart dragging).
- **WebKit limits:** 6 connections per host (6+ SSE streams starve other fetches — the page must hold at most one or two); hidden-window timers drop to 1/s (SSE keeps full rate; `background_throttling(Disabled)` did not change it) → the page's scan watchdog must not depend on timers while hidden.
- **D-3 confirmed:** localStorage is per port; a new port each launch also adds a WebKit data folder each launch → OQ12 (reuse the last port) plus a cleanup of stale per-port stores.
- **Portable (D-4), macOS:** `incognito(true)` writes nothing to ~/Library, but WebKit still creates per-user folders under /var/folders — state it in the portable status sentence.
- **Single-instance** uses `/tmp/<identifier>_si.sock`, shared by all users → a per-user socket path.
- **Signing:** without a signing identity the bundler leaves the `.app` unsealed; with `signingIdentity "-"` + `hardenedRuntime false` it verifies. A locally built ad-hoc `.app` launched three times with no Gatekeeper refusal; `spctl --assess` rejects it, so downloaded copies behave as today's (the owner's standing decision: ad hoc, no notarization). The ad-hoc designated requirement is the cdhash (changes every build). `hardenedRuntime` defaults to true, and a Node sidecar signed that way dies at start ("Failed to reserve virtual memory for CodeRange") → keep hardenedRuntime false (or allow-jit if ever enabled). The bundler does not sign Mach-O files in Resources (.node addons, libvips, gdu) → T-24's own innermost-first signing script stays.
