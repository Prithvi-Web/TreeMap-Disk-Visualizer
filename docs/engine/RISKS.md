# Risks (Phase 0)

What could break, what is hard to test, what is platform-specific, and what
could cost a user data, disk space or bandwidth. Each risk names the phase
that retires it and how. Severity is the cost to a user if it lands, not the
likelihood. Companion to [`CURRENT-STATE.md`](CURRENT-STATE.md) and
[`DESIGN.md`](DESIGN.md).

## A. Data, disk and bandwidth (the ones that matter most)

The near-duplicate job already excludes the flag; the exact finder does not (`CURRENT-STATE.md` §6) | CRITICAL — bandwidth, a metered connection, and the disk the user is trying to empty | Present in v5.0.1 | The first commit of Phase 5, test-first: every `Flag.CloudPlaceholder` and `dataless` node is excluded before bucketing, reported in the `notHashed` list, and a test asserts the finder never opens one |

| R19 | **Windows long paths, junctions, reparse points, `MAX_PATH`** | MEDIUM | `\\?\` prefix internally, `FILE_FLAG_OPEN_REPARSE_POINT`, reparse points as leaves | Phase 3 Windows; the edge-case generator; CI's Windows leg is the only place it runs for real |

| R22 | **The developer machine's C toolchain**: `cc` alone cannot link (command-line-tools SDK newer than Xcode 26.6's linker). `cargo` links fine | LOW (developer only) | The harness compiles its one C probe with `xcrun --sdk macosx clang -isysroot …` | Phase 1 |
| R23 | **macOS 27 resets loopback connections beyond the listen backlog**, which is why one existing test is red locally | LOW (test only) | Recorded in `CURRENT-STATE.md` §13 | Phase 1's test fix (≤ 64 sockets, same 200 requests) |
| R53 | **A volume mount point is walked when it is the scan root, or when a directory is swapped for one after its parent was listed.** `open_dir` in `windows.rs` reopens through a `MOUNT_POINT` reparse point whose substitute name is not `\??\X:`; a child mount point is a size-0 symlink-kind leaf that is never entered | LOW | Mirrors the legacy walker exactly: `fs.lstat` on such a junction reports a directory (libuv treats only `\??\X:` junctions as links) and libuv's `scandir` types every reparse child as a link, so both engines walk a root mount point and neither enters a child one. The 22 Sep 2026 security review rated this CRITICAL on the assumption that children were followed — they are not; the exposure is metadata of a volume the same user can already read, and every destructive action re-validates the live path | The Windows CI leg's first live run (question (b) of the eight); a root-at-mount-point case needs a second volume the runner may not have |
| R54 | **A lone UTF-16 surrogate in a Windows name is U+FFFD or WTF-8 depending on the libuv inside the Node that runs the legacy walker.** libuv before 1.47 replaces it (as `windows.rs` does); from 1.47 it keeps the surrogate as WTF-8 bytes. CI's Node 20 and the desktop app's Electron may not agree with each other | LOW | Unprovable here, and the edge fixture cannot plant such a name from Node (the JS string is converted on its way in). The rule and its reason stand at the top of `Record::name_string` | A live Windows comparison; if a leg shows a digest difference on such a name, the decision is per Node version |
| R55 | **A volume without file ids (the `FindFirstFileExW` fallback: FAT32, exFAT, some shares) reports every leaf as `withheld`, so `unreadableEntries = fileCount`** — true to the crate's contract, false to the user, whose files were all read | MEDIUM | The owner's decision, asked 22 Sep 2026. The recommendation: a missing file id (which only feeds the hard-link rule, and such volumes have no hard links) and a missing allocation (never meaningful on Windows, R-legacy: libuv leaves `blocks` at 0) do not make an entry unreadable; only a missing size or mtime does | The owner's word, then the rule in `stage_record` with a synthetic test of a whole fallback-derived listing |

| R25 | **Only Tier B exists here.** Tier A and Tier C bands cannot be verified on this Mac | MEDIUM | Reported as "not available on this machine", never as passed; CI runners (2–4 vCPU) stand in for Tier C with their noise stated | Phase 2 |
| R26 | **The legacy engines cannot hold Eco exactly** (Node cannot set QoS or I/O policy; gdu is a child process) | MEDIUM | Built as the Node shim: a per-worker duty clock, a worker cap, `nice` on gdu shards, and every answer says `source: 'node-shim'`; a governor that loaded but is not in force is reported as the shim too, never as a measurement | Phase 2 (done); the native walker's own workers are governed directly in Phase 3 |
| R27 | **Thermal and battery signals need Objective-C/IOKit calls from Rust** | LOW | `objc2-foundation` and IOKit through the `core-foundation` crates; a synthetic thermal state drives the tests | Phase 2 |
| R28 | **Sleep/wake**: a scan that keeps a drive awake, or resumes into a vanished mount | MEDIUM | Pause on will-sleep, resume from checkpoint on wake, re-probe the root | Phase 2/3 |
| R52a | **Eco and Balanced sit at duty 1.0 on 8 cores** (`max_workers × 1.0 / cores` equals the ceiling), so a competing process pulls the share below target with nothing the loop can add; measured as an 8 s Eco dip to 0.16–0.19 while `syspolicyd` ran, inside the band by 2.0–2.6 points | LOW | Recorded with the measurement in DESIGN §8.1; a third Eco worker on ≥ 8 cores is the candidate fix, to be measured, not assumed | Phase 8 tuning |

## H. Security surface of native code

| # | Risk | Severity | Where it stands | Retired by |
| --- | --- | --- | --- | --- |
| R44 | **Native code opens files.** A path that escapes the scan root, or a symlink swapped in mid-walk, opened by Rust | CRITICAL | `O_NOFOLLOW` + `O_DIRECTORY` descriptors, `openat` relative to the parent descriptor, never a full-path `open` from a stale listing (the mobile review's CRITICAL, re-fixed here); the core never writes to any volume except app-data; the same `pathGuard` rules apply before a path reaches napi | Phase 3 with a swap-in test |
| R45 | **Unsafe Rust.** `getattrlistbulk` buffer parsing is inherently `unsafe` | HIGH | The workspace lint set (`unsafe_op_in_unsafe_fn = deny`, no `unwrap`/`panic`/`indexing_slicing`), fuzz-style tests over truncated buffers, `panic = unwind` with `catch_unwind` at the napi boundary so a Rust panic becomes a stated engine failure and the legacy engine takes over | Phase 3 |
| R46 | **A panic or crash in the core takes the app down** | HIGH | Every napi entry is wrapped; a crash in the native engine marks it unavailable for the session with the reason and re-runs the scan on the legacy chain | Phase 3 |
| R52 | **A body-less `POST` is a CORS-simple request.** `POST /api/scan/:id/pause` and `/resume` (Phase 2) can be fired by any page a browser on the same machine renders, without a preflight, exactly like the existing `POST /api/compression/:jobId/cancel` and `/autopilot/policies/:id/approve`. The response is opaque and the scan id is a random UUID the page cannot read, so the request needs an id leaked by other means; CORS and the API token stay opt-in as before | LOW | Recorded here as the app's existing posture (loopback listener, unguessable ids, no persisted state touched by these two routes) rather than a one-off guard on two routes; a same-origin check for every state-changing route is a Phase 8 candidate that must land on all of them at once | Phase 8 (decision) |
| R56 | **A cancelled walk whose worker is wedged inside a kernel call cannot be joined**, and until 22 Sep 2026 `scanTake` joined it on Node's main thread — one dead SMB mount would have frozen the whole app | HIGH | After `scanCancel` the app polls up to `NATIVE_CANCEL_DEADLINE_MS` (5 s) for the walk to end, then abandons the handle: the thread and its slot stay in the module for the life of the process, freed only if the call ever returns. A walk that answers no listing batch for `NATIVE_STALL_MS` (30 s, the legacy walker's own per-directory bound) is cancelled the same way and the scan falls back to the legacy engines with that reason in `fallbackReason`. `scanTake` refuses a walk that is still running instead of blocking | An interruptible listing (`pthread_kill` / `CancelSynchronousIo` per platform) — deferred until a measured need |
| R57 | **The prebuilt module's only integrity check is its version string.** A same-architecture `treemap_core.node` tampered with in place, keeping `version()`, loads at full process privilege | LOW | The precondition is write access to the app's own resources, or control of `TREEMAP_NATIVE_MODULE` at launch — the same access that replaces the app itself; a wrong architecture or version fails closed to the legacy engines | A SHA-256 pinned in `package.json` and checked by the loader — a Phase 8 candidate, cheap |
